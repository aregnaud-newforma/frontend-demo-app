## Blind spots

1. a request naming no session is served the shared "demo" account — left open: the API's own fallback for a request the app under test never makes. Every E2E journey opens by seeding a session, and one that did not would share a single mutable record with every spec running beside it.
2. both pages show the error rather than stale data when a load has both — left open: reaching it needs a successful load followed by a failed refetch, and neither page ever refetches. The test that covered it stubbed `useAccount` and so proved the stub, not the page.
